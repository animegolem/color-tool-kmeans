# AI-IMP-136-batch-view

## BatchView — empty/selection/results states + three-panel layout

The core UI for the batch analysis feature. A new Svelte view component with three states: empty (< 2 pins), selection (2+ pins, not yet analyzed), and results (analysis complete with three-panel chart layout). Includes the batch analysis runner submodule that orchestrates grid composition → k-means analysis → result display.

### Out of Scope

- Values analysis (range finder, histogram, notan) — deferred per design doc.
- Configurable grid layout (auto vs fixed presets) — Phase 2.
- Comparison mode (two-image differential) — future EPIC.
- Export functionality — separate ticket (IMP-137).

### Design/Approach

**View states:**
1. **Empty** (< 2 pinned): Guidance text + "Upload media" button + tip about pin icon.
2. **Selection** (2+ pinned, no result): Live CSS grid preview of pinned images (from `previewUrl`), pin count, "Analyze" button, "Clear pins" button.
3. **Results** (analysis complete): Three-panel top row (grid composite | polar chart | palette strip) + two-panel bottom row (histogram | hue×lightness). All charts zoomable. "Re-analyze" and "Export Composite" buttons.

**Three-panel layout (results state):**
```
┌──────────┐ ┌──────────────┐ ┌────────────────┐
│ Grid     │ │ Polar Chart  │ │ Palette Strip  │
│ Preview  │ │              │ │                │
└──────────┘ └──────────────┘ └────────────────┘
┌────────────────────┐ ┌────────────────────────┐
│ Histogram          │ │ Hue × Lightness        │
└────────────────────┘ └────────────────────────┘
```

Uses CSS Grid for layout. Charts generated by existing `generateCircleGraphSvg`, `generateHistogramSvg`, `generateHueLightnessSvg` — fed from multi-analysis result store.

**Runner submodule** (`batch/batch-runner.svelte.ts`):
- `createBatchRunner(deps)` factory following established pattern
- Orchestrates: `composeGrid(paths)` → `tauriInvoke('analyze_image', { req })` with explicit `path` → store result
- **Critical:** Must NOT use `setActivePath()` or `analyzeImage()` from the compute bridge. The compute bridge reads a global `__ACTIVE_IMAGE_PATH__` variable (`active-image.ts`). Mutating this would leak the composite path into subsequent single-image analysis in Colors/Exports views. Instead, call `tauriInvoke('analyze_image', { req: { path: compositePath, ...params } })` directly and parse the response using the same Zod schema from `compute.ts`.
- Spinner with >150ms fade-in threshold (match HomeView `analysis-runner.svelte.ts` pattern)
- Error handling with user-facing messages

**App.svelte changes:**
- Add BatchView to the view conditional rendering
- Add "Batch" nav item between "Values" and "Exports"

### Acceptance Criteria

**Scenario:** Empty state with no pins
**GIVEN** the media bucket has images but none are pinned.
**WHEN** the user navigates to the Batch tab.
**THEN** guidance text is shown explaining how to pin images, with an "Upload media" button.

**Scenario:** Selection state with live preview
**GIVEN** 4 images are pinned.
**WHEN** the user navigates to the Batch tab.
**THEN** a 2×2 CSS grid preview of the 4 pinned images is displayed.
**AND** "4 images pinned" label and "Analyze" button are visible.

**Scenario:** Running analysis
**GIVEN** 4 images are pinned and the user is on the Batch tab.
**WHEN** the user clicks "Analyze".
**THEN** a spinner appears (after 150ms if still running).
**AND** the grid composite is built, then k-means analysis runs.
**AND** results appear in the three-panel layout with polar chart, palette, histogram, and hue×lightness.

**Scenario:** Changing pins clears results
**GIVEN** batch analysis results are displayed.
**WHEN** the user unpins one image from the media bucket.
**THEN** results clear and the selection state is shown with the updated pin set.
