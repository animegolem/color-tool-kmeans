## C1-H25 — detected document contradictions must reach the guard

This is the incomplete part of H22, not a new protocol design or an observed WebKit schedule.

**Source evidence at the reviewed Round02 hashes:** `src/driver.rs429-457 renderer_receipt` checks only native label versus payload label, then records and queues any href/incarnation. A label mismatch merely returns Err, without poisoning the captured child or publishing a runtime failure. `wait_initial_admission` uses a positive-only matcher: an unmatched wrong-document receipt can remain in EventInbox.backlog while a later matching receipt satisfies the case. The page-load callback likewise computes exact expected URL for both events, but calls the protocol only for Started; a contradictory Finished is just logged. In contrast, protocol.bootstrap now correctly poisons a wrong href.

Thus the bootstrap regression proves only the bootstrap boundary. A contradictory document-start/receipt observed on an already-active child does not itself revoke that child's authority; a subsequent ownership call with its still-valid native-bound tuple can mutate the real registry. Unknown native sources must fail the experiment without selecting a successor from renderer data.
