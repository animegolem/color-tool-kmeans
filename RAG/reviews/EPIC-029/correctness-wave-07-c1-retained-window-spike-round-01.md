## H16 protocol boundary for the spike

Each child is created with native-random, never-reused `(incarnation, bootstrap_proof, session_candidate, request_id)` embedded in that child's static main-frame initialization script. The script creates one random `document_instance_nonce` per JS instance and keeps it stable for retries. The bootstrap key is the complete five-field tuple. The native values provide the one-shot capability; the JS nonce is only a diagnostic/conflict discriminator and must never be called a native document ID.

The pure state table is:

| Native state | Request | Required result |
| --- | --- | --- |
| `AwaitingEligibleLifecycle` | first exact pre-minted key with intended renderer-reported URL | pin the full key; `NotReady`; no admission/registry allocation |
| `EligibleUnadmitted` | pinned key, or the first exact key if no early receipt | activate the pre-minted session once |
| `Active(original_key, session)` | byte-identical original key | `ConfirmedExisting` for that same admission; same session, no new proof/session/registry allocation |
| `Active` | changed request ID, proof, session candidate or diagnostic instance nonce | `Conflict`; no mutation |
| `Retired` or `Poisoned` | any request, including the old exact original | terminal `Retired`; no confirmation, renewal or mutation |

The first allowed local navigation-policy call is only an eligibility guard. Any later/ambiguous call denies and retires; only the first captured-current eligible `Started` can move `AwaitingEligibleLifecycle` to `EligibleUnadmitted`. `Finished`, renderer receipt, URL equality and JS nonce never advance native authority. PageLoad/policy URLs are native callback observations; the document-start IPC `href` is explicitly renderer-reported diagnostic data. If an unexpected `about:blank`/wrong-frame request or lifecycle is observed, poison the child, without claiming the renderer URL proves frame identity. A success reply returns only status and a correlation digest; it never carries a proof, session candidate or successor identity. Because the static script already has its own child's values, a lost acknowledgement can be recovered by the exact original while that admission remains active.

This conditional table preserves H16 but does not prove binding. A later JS instance can generate a different nonce and is rejected in the tested honest path; the public surface still cannot establish that a renderer could not replay the old full tuple before native detects navigation. The policy/initial-empty-document premise remains open even after a successful run.

## Proposed pure tests

No-UI pure testing is achievable. These tests compile Tauri types but never call `tauri::Builder`, `generate_context`, `App::build/run`, `WindowBuilder` or `add_child`:

1. Early exact request returns `NotReady`, pins the full key and leaves protocol allocation count and real `ArtifactAccounting` unchanged; the same request after eligible lifecycle activates exactly once.
2. Exact-original duplicate while active returns the same pre-minted session and leaves admission/session counts and real accounting byte-for-byte equal. Simulated lost/withheld first acknowledgement does not alter that result.
3. Each single-field conflict, including a different diagnostic instance nonce, rejects with no state/accounting change; tests explicitly state that nonce is not document authority.
4. Retirement is monotonic: known-session and acknowledgement-lost exact-original requests both reject after retirement and cannot activate a successor.
5. Seed one real `Snapshot` group of 4096 bytes with its native initial lease. Assert the exact baseline: resident/live-owned `1 group/4096 bytes`, eligible/claimed `0/0`, active leases `1`, reclaim candidates `0`. A valid current acquire changes active leases to `2`; stale bootstrap/acquire/release and held old completion preserve the exact then-current snapshot and retained native lease.
6. Valid current release is idempotent only for its exact lease; protocol rejection occurs before invoking registry mutation. No retirement path implicitly releases, reclaims or deletes the test group.
7. Unique child-label allocation yields `c1-peepxt-1..N` monotonically and refuses reuse/double-close bookkeeping.
8. Trace tests cover contiguous sequence/time fields, actual versus forced provenance, snapshot serialization, create-new output/ledger rejection, write/flush taint, missing case receipt, timeout and terminal-finalization failure.
9. CLI/config tests prove default/help/validation do not enter a Tauri-construction function and require empty configured windows, exact product/identifier, local assets and bundle false.

These tests prove application transitions and gate structure only. They cannot substitute for native window/WebView creation, callback ordering, close/removal, bounds, storage, or platform delivery.

## Proposed bounded runtime cases and success receipts

The future run is six cases under one parent. Every case needs `case-started`, all named required receipts, exact before/after state/accounting, and one ordered `case-completed`; any trace error, missing required receipt, timeout or inconclusive safety transition prevents terminal success and exit 0.

1. **Parent/first child and admission.** Record non-null parent `ns_window`, initial geometry, unique child-1 create request/return, every actual navigation-policy/PageLoad callback and document-start IPC with observed URL/order. Admission must occur only after an actual eligible `Started`. If IPC precedes it, require actual `NotReady` then exact retry; if it follows, direct activation is allowed. Exact-original lost-ack recovery must return `ConfirmedExisting` with unchanged session/allocation/accounting. A conflicting instance request rejects unchanged. Any observed unexpected `about:blank` cannot activate; absence is recorded only as finite non-observation.
2. **Known A -> B in the same parent.** While A has observed its admission, perform one valid A acquire (active leases `2`), retire A before close, record close return and old-label absence, and add uniquely labelled B. After B activation, B remains current; releasing held A bootstrap/acquire/release controls returns retired before registry access. Parent pointer is unchanged, A lease/native owner remain counted, and accounting remains exactly resident/live-owned `1/4096`, active leases `2`, eligible/claimed zero.
3. **Acknowledgement-lost A -> B.** Activate another child A but hold/omit its first renderer success receipt; hold an exact-original retry at a labelled native control boundary. Retire/close A, activate fresh B, then release the retry. It must reject `Retired`, allocate nothing, reveal no B credential and preserve B/protocol/accounting. A missing old renderer callback is `not-observed`, never cancellation proof; native receipt/release/rejection are separate required rows.
4. **No same-child renewal.** In a dedicated admitted child, request a same-URL reload. Require the actual policy callback, denial and terminal retirement. If no new `Started` occurs, record only non-observation, not a new-document claim. The still-rendered old page must fail authority calls. Recovery requires the next unique child. Unexpected policy behavior makes the case fail/inconclusive; the driver must not bypass it.
5. **Old completion and explicit document guard.** Hold an A-owned native completion whose commit would acquire the real group; replace with admitted B and release it. Native rejects before mutation and accounting stays exact. Separately submit an explicitly labelled A payload to B; B's static guard must emit an execution receipt marked stale and perform no renderer/native mutation. Ordinary late Tauri callback routing and this forced guarded delivery remain different evidence classes.
6. **Retained identity, resize and finalization.** Across all swaps, require the same non-null parent pointer, no parent `Destroyed`, no last-window `ExitRequested`, and all unique old labels absent. Programmatically change parent inner size to a distinct fixed value; after actual `Resized`, require child bounds position `(0,0)` and size equal the observed parent inner size (allow only a declared one-physical-pixel rounding tolerance). Record final registry/native-test-owner snapshot. Then keep the event receiver and watchdog alive until all six completions and durable terminal-row flush are acknowledged on the main loop; only then request controlled exit. The expected final parent shutdown is recorded separately from the swap interval.

Eval/invoke dispatch acceptance is never execution. A required renderer effect needs an explicit JS IPC receipt with observed child label/URL/incarnation/instance nonce. An absent eval/invoke/PageLoad callback is `not-observed` within the bound and cannot satisfy close, cancellation or stale rejection. Per-case deadlines and the five-minute watchdog only fail the experiment; they never retire ownership or make a safety transition.

## Initial-binding and observation limits

- Incognito's documented nonpersistent datastore does not prove every global WebKit side effect absent; the run remains local/test-owned with no production data.
- Pure tests and a finite runtime run do not accept production `tauri/unstable`, C1-C3/IO/consumer integration,193-B, another platform or any retention/deletion behavior.
