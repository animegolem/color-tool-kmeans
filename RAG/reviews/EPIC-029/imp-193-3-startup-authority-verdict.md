Native receipt handling selects the actual invoking child and poisons it on context contradiction before receipt delivery. An initial wrong-document report therefore fails closed; an unavailable/dropped receipt does not run the bootstrap continuation. An exact pre-Started call can only pin the original and receive NotReady. The later retry repeats that original. This excludes the older renewing N+1 challenge counterexample under the trusted packaged-local startup model. It does not authenticate renderer diagnostics against hostile code.

The report's requirement to retire on replacement is a proposed implementation obligation, not evidence that the frozen harness detects every replacement. Likewise, recovery by creating a new child is a product requirement, not a production feature demonstrated here. Ordinary pending command-response routing and other platforms remain unaccepted.
3. **193-3-D3 — Put the actual product choice to the owner.** Recommend the trusted packaged-local, one-document-per-unique-child contract. Reload, later document navigation, content-process loss, contradictory context or ambiguous startup must never renew the same child's authority. Recovery replaces the interface child inside the retained OS window; native-owned work/data have independent lifetimes. Ordinary image loading, repaint and Svelte view changes are not document replacement. Transient renderer-only input/focus may need restoration and cannot be promised preserved before the visible test. Approval of this contract does not establish lifecycle detection or relax the existing R/native-owner rules.
